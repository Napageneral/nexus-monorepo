# CPO-005 — Incremental Object Convergence

**State:** not started
**Depends on:** CPO-004
**Repositories:** selected by the one candidate in scope

## Goal

Turn the two-object proof into a repeatable, bounded process for migrating one
additional business-needed candidate at a time.

## Scope

- Select exactly one next candidate from the active evidence chronology and
  business need.
- Classify it as `reuse`, `alias`, or `create` using the canonical eligibility
  test.
- If reused, attach only the required Facet or relationship semantics.
- If aliased, update vocabulary without creating identity or storage.
- If created, register one complete type and have an agent publish its canonical
  revision through the generic operation.
- Verify the object, move its exact consumers, and delete the code and language
  that this convergence replaces.
- Publish a small continuation-ticket template for later independent
  candidates.
- Keep all unselected candidates in the vocabulary ledger without treating
  them as approved object types.

## Acceptance

- One additional candidate completes the entire convergence loop without
  changing the kernel interface.
- No domain-family migration or bulk declaration is required.
- Reuse and alias outcomes are considered successful migrations when no new
  object is warranted.
- The continuation template is small enough to execute one object at a time.
- Remaining candidates are explicitly undecided or prioritized; none are
  silently promoted from packet or table nouns.
- Replaced disabled projector, decoder, adapter, and compatibility code for the
  selected concept is removed in the same ticket.

## Validation

- Candidate decision receipt with evidence and rejected alternatives.
- Interface-level projection or native-reuse proof, as applicable.
- Exact consumer cutover readback.
- Deletion and vocabulary scans.
- No regression to Purchase Order, Product Revision, or native Channel proof.
