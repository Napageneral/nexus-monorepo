# CPO-006 — Legacy Deletion and Foundation Closure

**State:** not started
**Depends on:** CPO-005
**Repositories:** nexus umbrella, Nex core, and MoonSleep

## Goal

Remove foundation-era machinery made obsolete by the proven kernel and close
the foundation without pretending every future domain object has migrated.

## Scope

- Delete duplicate active registry, target-adapter, resolver, compatibility,
  projector, and decoder paths that have no remaining consumer.
- Prove that every retained legacy path is still required by a specifically
  named unmigrated consumer; orphaned or disabled code does not remain merely
  for caution.
- Reconcile the canonical spec, registry contract, vocabulary ledger, and
  continuation-ticket template.
- Run the complete SQLite/PostgreSQL cleanroom with projected objects, native
  Channel, Observation targeting, Core Graph, agent projection, historical
  interpretation, and replay.
- Obtain independent review of the foundation interface and deletion boundary.
- Archive this foundation board while leaving later one-object convergence
  tickets active independently.

## Acceptance

- Only one canonical declaration path exists for newly registered projected
  objects.
- No obsolete per-object path remains for Purchase Order, Product Revision, or
  the CPO-005 candidate.
- No disabled projector or historical decoder remains for those converged
  concepts.
- Every retained legacy surface names its exact remaining consumer and follow-on
  convergence ticket.
- The kernel interface remains the two primary operations defined by the spec.
- Independent review finds no second authority, duplicate head, fuzzy resolver,
  or cursor rewrite.
- No production object, table, or history is destructively removed without
  separate explicit authorization.

## Validation

- Exhaustive declaration, adapter, resolver, projector, decoder, and physical
  vocabulary scans.
- Full cleanroom and replay suite on exact current main.
- Independent standards and spec review.
- Final corpus-link and workplan archive validation.
- Production-writes and historical-cursor readback remain zero unless separately
  approved receipts are attached.
